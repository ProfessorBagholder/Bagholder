# Brief 48: after #525, build the page on Node 26 once it is long-term support (2026-10-28)

A follow-up, not part of #525. The owner has seen it.

## Why

- **Node only builds and tests the page.** The app never runs on it: the release archives and the image carry the built page, not Node.
- **Node 22 is in maintenance:** security and critical fixes only since 2025-10-21, with support ending 2027-04-30.
- **Node 26 becomes long-term support on 2026-10-28,** supported until 2029-04-30. Node 24 is supported until 2028-04-30.
- **Node's own guidance:** "Production applications should only use Active LTS or Maintenance LTS releases" ([nodejs.org](https://nodejs.org/en/about/previous-releases); dates from [endoflife.date](https://endoflife.date/nodejs)). So the move waits for 26's long-term support to begin.
- **The page's tools accept Node 26** (`web/package-lock.json`):

  | Tool | Accepts Node |
  |---|---|
  | Vitest 5 | ^22.12, ^24 or ≥26 |
  | Vite 8 | ^20.19 or ≥22.12 |
  | vite-plugin-svelte 7 | ^20.19, ^22.12 or ≥24 |
  | Playwright 1.63 | ≥20 |

- **No reason is recorded for 22.** It is in the history's first commit, and no document mentions it.
- **One mismatch today:** the page is type-checked against Node 24 (`@types/node` ^24.13), but built on 22.

## Required

1. **Every place that sets Node 22 moves to 26:**
   - `.github/workflows/tests.yml`: the three `setup-node` steps;
   - `.github/workflows/release.yml`;
   - `rust/Dockerfile`'s web stage (`node:22-slim`);
   - the README's "Node.js 22 or newer".
2. **`@types/node` to ^26,** so the type check matches the build.
3. **The floor stated where npm reads it:** `"engines": {"node": ">=26"}` in `web/package.json`, so a build on an older Node says why.
4. **Verified on 26:** `npm run check`, `npm test`, the full e2e, the container job and a release build (`release.yml` on a pre-release tag, or the same steps run by hand). Paste the page's transfer size and the archive's size before and after.
