# Brief 78: A link to a running copy, for the people developing the app

Line numbers are from master at aeccf555 (#634 merged). Nothing in this brief names the owner's account, domain, provider or tunnel inside the repository: the repository is public and the app serves every user. The one app change is generic and off by default; everything about links is tooling on the development server, outside the repository.

## 0. Why

The owner (2026-10-26, chat): the sessions developing the app must be able to hand them a working browser link to test whatever branch or fix is in hand, from any of their devices, with nothing installed on the device and nothing left running afterwards; then a fixed address for their main copy that stays put; after that, short-lived demo links for other people showing made-up data with orders off; sign-in with other providers last, if ever, since anyone can put their own proxy and login in front.

What stands today. `admitted` (`rust/crates/server/src/http/mod.rs:361-376`) lets a request in when the peer is loopback (`peer_ok`, `:379-388`), the Host header is exactly `127.0.0.1:<port>` (`host_ok`, `:390-402`) and a write comes from the page (`sec-fetch-site: same-origin`, or the app's own header). Through any proxy running on the machine the peer is loopback but the Host is the proxy's name, so the page, `/api` and the event stream all get 403 (held by `tests.rs:52`, `test_only_the_page_on_this_machine_gets_in`, its `evil.example` case). The architecture says what remote access is (`docs/architecture.md:173-174`): the server answers only its own machine unless the person turns on remote access, which goes through a tunnel or reverse proxy the person already trusts; the app manages no certificates. The owner's decision of 2026-10-04 (remote access with a sign-in: not now) is superseded at the owner's word of 2026-10-26: the sign-in is the proxy's, and the app's part is to accept the proxy's name. The page needs nothing: its fetches and its `EventSource` use relative URLs (nothing in `web/src` names a host), and its live stream sends a keepalive every 15 s (`stream.rs:140`, `events::KEEPALIVE`), under any proxy's idle limit (Cloudflare's is 100 s).

## 1. The app change: an opt-in list of names the server answers to

One PR, released MINOR (a setting a user can set is new to them; nothing on the page changes).

- `BAGHOLDER_HOSTS`: a comma-separated list of exact host names as the Host header will carry them (`name` or `name:port`), read where `BAGHOLDER_BIND` is read (`main.rs:191`), lowercased, held on `App` beside `bind_host` (`app.rs:261`). Unset or empty: today's behaviour, byte for byte.
- `host_ok` admits a Host equal to `127.0.0.1:<port>` as today, or equal to one listed name. Nothing else: no wildcard, no suffix, no port ignored. `peer_ok` is unchanged, so a listed name is accepted only from loopback (or from the container's bridge when bound beyond loopback, as today): the proxy's connector on this machine is the only way in.
- An entry that is empty, has a space, or is not a host name with an optional port refuses the start with one line naming the entry, the way a bad `BAGHOLDER_PORT` does. Fail closed.
- `from_the_page` is unchanged: on the proxy's name the page is same-origin with its API.
- Tests, in or beside `test_only_the_page_on_this_machine_gets_in`: (a) the list empty, every existing case as it is; (b) a listed name from loopback, 200 on a read and on a write from the page; (c) the same name from a peer that is not loopback, 403; (d) near misses, each 403: the name with a port when the list has none, a longer name ending in the listed one (`evil-dev.example.com` against `dev.example.com`), another name; (e) `DEV.example.com` admitted (the Host is lowercased before the check, `mod.rs:369`); (f) the parser: an entry with a space, an empty entry, each refused naming its text.
- Docs: `docs/architecture.md:173-174` name the variable; `docs/decisions.md` records the decision and what it supersedes; the document on running the app gets one paragraph: what to set when a proxy with a login sits in front, and that the app has no sign-in of its own, so the proxy's is the only one.
- Not in the app: Cloudflare, Tailscale, GitHub, any domain, tunnel or certificate; OAuth; an Origin list; anything on the page.

## 2. The tooling, outside the repository

Built by the CTO as a command every session on the server can run, kept outside the repository (the sessions' own tools folder), with its settings (the domain, the tunnel, the login policy) in a file there and nowhere else. Before it, the smoke test's leftovers go: the Portless proxy on port 1355, the worktree `/tmp/portless-smoke/bh-wt` registered in the owner's checkout (`git worktree remove --force`, then `prune`), the folder `/tmp/portless-smoke` with the tailnet certificate and key.

1. **`preview <name> <ref>`** builds `<ref>` (a branch or commit) in a detached worktree of the session's own, starts the built binary with the variables the repository requires of every scratch copy (`CLAUDE.md:86`: `BAGHOLDER_EXIT_WITH`, `BAGHOLDER_DRY_ORDERS=1`, `BAGHOLDER_NO_BROWSER=1`), a free `BAGHOLDER_PORT`, its own `BAGHOLDER_HOME` holding a made-up book unless asked otherwise, and `BAGHOLDER_HOSTS` set to this preview's one public name; prints the link once the copy answers; refuses a leading option, so no flag of the publisher's can be passed through the command.
2. **The link opens from any device with nothing installed, after the owner's sign-in at the gate** (their GitHub identity). Cloudflare Access in front of a named Cloudflare Tunnel is the available choice: the connector is installed and running on the server already, the free plan covers one person's use with GitHub as the login, and the live stream works through it. The gate is enforced twice: the Access policy on the application, and the connector itself requiring Access's token (`originRequest.access.required` with the application's audience tag), so a mistake in the policy cannot open a copy. The owner's data never passes except through their own sign-in; they accept that the proxy terminates TLS.
3. **One public name per preview** (`<name>.` under one subdomain of the owner's choosing), under one wildcard DNS record, one wildcard Access application and one tunnel: the preview's route (its name to `127.0.0.1:<port>`) is added when it starts and removed when it ends, and the connector runs only while a preview runs. The CTO checks the mechanism against Cloudflare's current documentation before building (ingress by hostname, wildcard applications, the connector's token check). Quick Tunnels are not an option: they do not carry server-sent events, and the page's live updates are server-sent events.
4. **The fixed address for the owner's main copy**: the same gate, one fixed name, pointed at the copy the owner designates. It stays.
5. **Cleanup is the wrapper's, on every way out** (a normal stop, a hangup, the wrapper killed): the copy exits with the session (`BAGHOLDER_EXIT_WITH`), the route is removed, the connector stops when no preview remains, the worktree is removed and pruned. Nothing is published unless a session runs the command, and the session that starts a preview ends it.
6. **Demo links**, after 1 to 5 work: `demo-<name>` with no login, the copy run from the container image (CI builds `bagholder:ci`; docker is on the server) with a made-up book and `BAGHOLDER_DRY_ORDERS=1`, a time limit after which the wrapper stops it, everything removed at the end. Never a real book, never a copy that carries a login. The container is the box an internet-facing copy runs in.
7. **Sign-in with other providers**: not built. The running document says any proxy with a login works once its name is listed.

**§2 amended (2026-10-27, the owner's decision).** The owner asked whether previews need a Cloudflare account and a domain at all. They don't. **Previews go over Tailscale Funnel, on the Tailscale account this server is signed into** ("yes it can use the Tailscale account the server is signed into"). That replaces items 2 and 3 for previews:
- **The link.** It is `https://<machine>.<tailnet>.ts.net[:port]`, public, opened from any device with nothing installed. Funnel and HTTPS are already enabled for the server's node (its `CapMap`). Funnel's serve proxy is Go's `httputil.ReverseProxy`, which passes the visitor's Host (`r.Out.Host = r.In.Host`) and flushes `text/event-stream` at once, so the live stream works.
- **Ports.** Funnel serves only 443, 8443 and 10000, and the page's URLs start at the root (`/api/…`), so each preview needs a port of its own: at most three previews at once. On this server the agents' own Funnel (#639) takes one of the three while it runs.
- **`BAGHOLDER_HOSTS`.** Set to the name exactly as the Host header carries it, with `:8443` or `:10000` on those ports.
- **No login in front.** Anyone who finds the name can open a preview while it runs; the name is in public certificate logs. So a preview runs only a made-up book with `BAGHOLDER_DRY_ORDERS=1`, never a real book. The "unless asked otherwise" of item 1 is withdrawn.
- **Foreground only.** Funnel is started in the foreground, never with `--bg`. A foreground config is deleted when the command ends, even when it is killed (plan #572 §4.3a, Tailscale's source at v1.104.2). The wrapper's cleanup then needs no Cloudflare route or connector. After a session, `tailscale funnel status` shows nothing of the preview's.
- **The fixed link to the owner's main copy (item 4)** holds real data, so it keeps a login in front: Cloudflare Access on a named tunnel, with a domain the owner names then. Rule 0 stands. It comes after the previews work. Quick Tunnels stay out: Cloudflare's docs say they "do not support Server-Sent Events (SSE)".
- **The order is unchanged:** the agents build, then the coin units, then the preview tooling.
