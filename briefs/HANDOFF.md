## 3. The review method

1. Read the brief, then the diff; for every required change, find its code and the test that holds it. Fetch a PR into the review clone: `git fetch origin pull/N/head` then `git update-ref refs/heads/pN FETCH_HEAD` (one ref per fetch; two refs in one fetch leave `FETCH_HEAD` on the first).
2. Plant the reverse of each key change and confirm its test fails: `<scratchpad>/plant590.sh "<name>" <file> '<old>' '<new>' -- -p <crate> --test <target> <filter>` (restores the tree). One build folder per clone (`CARGO_TARGET_DIR=$PWD/target RUSTC_WRAPPER=`), under `flock -o /tmp/bagholder-build.lock nice -n 10 cargo test --locked …`. The engine plants print nothing through the script's grep; rerun them raw.
3. **The sweep, before clearing any pull change:** the every-shape book (`Generated::shaped(size, today, &shapes)`, `SHAPES` + `STATED_OTHERWISE` + `ASSIGNED`) over seeds 1–12 and a second `today`, asserting every account's cash and units agree with the broker (`cash_of`, `units_of`, summed over a linked set), `report.statements.unreconciled` empty, `report.suspect` empty. Diagnose a disagreeing account by listing its transactions against the stand-in's rows. The scripts `plantsNNN.sh` in the scratchpad show the pattern.
4. Check outside facts against a primary source. A recorded page holds the part the reader reads, first line saying what was cut.
5. Full suites only on CI; never dispatch a run or push a throwaway branch; rerun a CI job only for a failure outside the code its log names (quote it). Read failing CI logs yourself (`gh api repos/…/actions/jobs/<id>/logs`).
6. This server's CPU is slow for model work; don't benchmark models here.
