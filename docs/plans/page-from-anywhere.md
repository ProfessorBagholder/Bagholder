# Plan: the page from anywhere, behind Cloudflare Access

The owner's ask, 2026-10-29: open their Bagholder from any device, not only one on their tailnet, behind a Cloudflare or GitHub sign-in, and anyone who wants the same can switch it on. Bagholder runs where the person runs it (often their own laptop), so the page is reachable while that computer is on and awake. The decisions are in `docs/decisions.md`, 2026-10-29. The rules are in `SPEC.md`, remote-1 to remote-4.

Paths are relative to `rust/crates/server/src` unless they start with `web/` or `docs/`.

## What is built

- **The address.** The person's Cloudflare domain, `app` by default, through a Cloudflare tunnel of the page's own (`remote::cloudflare`, its own folder `remote/cloudflare`). It is made with the same Cloudflare sign-in as the agents' tunnel, and the page keeps its own copy, so removing one never strands the other. It runs to the page's port, starts again with Bagholder while it is on, and is never opened by a copy (`BAGHOLDER_EXIT_WITH`).
- **Cloudflare Access in front.** Bagholder makes an Access application named for the address with the token the person makes on Cloudflare's own page (`remote::TOKEN_PAGE`, filled in: Access's applications and login methods, to edit). The tunnel's sign-in manages tunnels and DNS alone. The application allows one login method, Bagholder's own, and one rule: that login method and the person's email. Everything else is Cloudflare's default.
- **Bagholder's own GitHub sign-in.** Cloudflare's GitHub login is a GitHub app that someone registers, and GitHub names it on its sign-in screen. Bagholder never takes one the account has for something else. It posts a manifest (`remote::manifest`) to GitHub from the page, in a tab opened at the click. The manifest makes a private app named "Bagholder at" and the domain, cut to GitHub's 34 characters, allowed to read the email and nothing else, and signing in through the team's own callback. GitHub sends the person back to `/api/remote/github/made`, which takes only a manifest this Bagholder handed out, and Bagholder adds the app to Cloudflare as its own login method. The app's secret is kept only until Cloudflare holds it. GitHub won't make two apps with one name and lets no app delete one. So the sign-in is made once for a domain and found again by its exact name (`remote::login_of`) at every later set-up, and Remove keeps it.
- **The gate** (`http::remote::gate`, before the page's own gate, for the address's name alone). It takes a request only from this computer (the tunnel's connector), with Access's signed pass (`Cf-Access-Jwt-Assertion`) for this application and the email (`remote::check`). The pass must be RS256, signed with the team's keys (asked again for a new key, at most once a minute), name the application's audience tag, be issued by the team, be within its times (a minute's leeway), and name that email. A write also needs `X-Bagholder` or a same-origin fetch. Anything else gets one sentence, and the refusal is logged with its method, path, peer and User-Agent. A pass from another team asks Cloudflare for the team's address again (a team renamed), at most once a minute.
- **The check from outside** (`http::remote::check_while_coming_up`). From the moment the tunnel starts: every 5 seconds for a minute, then every 15, for up to 10 minutes. The name is looked up in public DNS, never this computer's resolver (which may still hold an answer from before the name existed), and asked as a stranger would. It is ready when it sends to the team's sign-in. Each try's result goes to the panel; it gives up with the reason only at the end.
- **The panel** (`web/src/lib/RemotePanel.svelte`, the menu's Open from anywhere). One list of numbered steps, each done, to do now, under way and where, failed with what to do, or still to come. The steps are the connector, the Cloudflare sign-in, the token (with a Zero Trust team made first where the account has none), Bagholder's GitHub sign-in, the address and the email, the tunnel starting, and the check. Then a ready screen with the address to open. Remove asks first, says what it is doing, then what went and what stays.
- **Remove.** It deletes the Access application, the address's DNS record and the tunnel at Cloudflare, and forgets the token and the page's files. It also forgets the Cloudflare sign-in when no agents' tunnel uses it. It keeps Bagholder's GitHub sign-in, as above. It says what stays in the person's accounts and links each: the token and the sign-in's tokens on Cloudflare's API tokens page, and the GitHub app. Deleting a token at Cloudflare takes the right to make tokens of any kind, which Bagholder never asks for.

## Found on the way (2026-10-29, on the owner's account)

- A new Access application is not enforced for its first seconds. Requests reached the tunnel unsigned 2 to 4 seconds after one was made, and Bagholder's own check refused them.
- Cloudflare keeps a team sign-in for 24 hours by default ([session management](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/session-management/)) and lets it into every application that allows the person, without asking the identity provider again. Revoking on GitHub doesn't end it.
- After a team rename, Cloudflare kept the old team name. Its sign-in page showed it, and its last hop on the application's own name (`/cdn-cgi/access/authorized`) answered "Unable to find your Access organization" until the team name was updated in Zero Trust's overview. A browser holding a cookie from before the rename kept getting that page until its site data was cleared.
- GitHub's manifest form refuses the email permission under its REST name `email_addresses` ("Default permission records resource is not included in the list"). It takes `emails`.

## Not included

- Other tunnels for the page (Tailscale Funnel, ngrok).
- More than one email, or a GitHub organization rule.
- Deleting the GitHub app or the token at the end. GitHub and Cloudflare leave both to the person, and the removed screen links them.
- Making the Zero Trust team, which only Cloudflare's dashboard does. The panel links it.
