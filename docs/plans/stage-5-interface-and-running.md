# Plan: stage 5, interface and running — only what changed reaches the screen, every failure is seen, access and agents through one interface, and the app runs as a service that updates safely

A done-contract (`PLAN.template.md`). Stage 5 of the order of work in `docs/design-review.md`; the targets are `docs/architecture.md` §12 (interface and access), §13 (data flow), §14 (AI agents), §15 (failures are seen) and §16 (running it). Built in parts, each merged when its criteria are green: **A1** data flow, **A2** the Markets context on the new wire, **B** failures shown, **C** access and agents, **D** running. A and B need no decision below; C and D wait for the owner's answers on the items that concern them.

## For the owner to decide

1. **Whether a release install sets itself up to start at login.** The architecture has the app install itself as the operating system's service (a login item on the Mac, a user service on Linux, a logon task on Windows), so it is running whenever you are signed in and after a crash, and a bracket's watched stop is guarded without a terminal open. The alternative is a command you run once (`bagholder service install`). Recommendation: a copy installed from a release sets itself up on its first start, and `bagholder service uninstall` takes it off; a copy built from a checkout (`cargo run`) never does. If not taken: the command only, and the app runs only while its terminal is open, as now.
2. **Whether access from beyond this machine needs a key.** Today, in the container (which listens beyond loopback so Docker can publish it), anything that can reach its port can place an order by sending two made-up headers. The fix that holds is a key: when the app listens beyond loopback, a browser is let in only after the key (a random string the app writes to its data folder and prints at start) is entered once, kept after that in a cookie only that browser holds; agents never use it (they come through MCP, item 3). Jupyter and Syncthing do this. Recommendation: required whenever the app listens beyond loopback; nothing changes on this machine's own address. If not taken: the container stays reachable by anything on its network, and it must never be published beyond loopback.
3. **Whether the AI agent tools include placing and cancelling orders.** The decisions say agents come through the MCP tools only and that agent trading is your choice. MCP clients (Claude among them) ask you before each tool call unless you tell them not to, and the protocol marks order tools as ones that change things. Recommendation: the order tools are included, marked as changing things, and every order an agent asks for goes through the same gate as yours and is recorded as the agent's; whether your client asks before each call is set in the client. If not taken: agents read the book and keep the journal and watchlist only; no order tool exists.
4. **Signed releases, and who holds the signing key.** An update is installed only if its archive carries a signature made with Bagholder's release key; the key that checks it is built into the app. The private key lives only as a GitHub Actions secret of the repository. If it is ever lost, the next release is installed by hand once (a new key ships in it); no copy of the private key exists anywhere else unless you want one. Recommendation: as described. If not taken: updates are checked by their checksum only, which proves the download is whole, not who made it.

## Scope

**A, data flow (§13)**, built as **A1** (everything below but the Markets context) and **A2** (the Markets context and the heatmap on the new wire: their prices are the earlier readers' floats in the earlier store, and move only by reading the watchlist's and the tiles' quotes through the new quote readers into the market cache, as the holdings' are: a piece of its own). The engine's change report (`Moved`, today computed and thrown away) becomes what the server sends: each subscription's rows that moved, their changed fields, numbered, resumable. The page subscribes per screen (the header; each tab's cards under the current filters; an open instrument), long lists are paged, the page keeps what it loaded in the browser's own database and asks only for what changed since, and on-demand reads are answered "unchanged" when they are. Quotes are read for what a screen shows. The markets context and the heatmap move onto the new wire (exact decimals, the last "stage 5" entries in `web/src/no_money_arithmetic.test.ts`). The four tests of §13 are built.
**B, failures shown (§15).** Every discarded error in the server and page is dealt with: a write that fails fails its operation, a read that fails is a failure of the source or store it belongs to, shown where §15 says; health per source is structured on the wire, not one joined sentence; the page says when the app cannot open its book. A scan test holds it.
**C, access and agents (§12, §14).** Host, Origin and fetch-metadata checks on every request whatever the bind address; a per-install write token in place of the constant header; the remote-access key (item 2); broker credentials in the operating system's keychain; one MCP server built into the binary whose tools are generated from the interface's declared operations, with the filings MCP server folded into it.
**D, running (§16).** The supervisor restarts after a crash; an update waits for no order request in flight, snapshots the book and market cache, swaps, and counts the new copy healthy only when it answers its health route with the book open; otherwise it restores the previous copy and the snapshots. Releases signed (item 4). Service install (item 1).

Out of scope, on purpose: the page's own structure and the cutover (stage 6: shared components, one overlay manager, accessibility, removing the Python and Go apps and `ledger.html`); moving settings, feeds and notifications off the old `bagholder.db` (stage 6, with the cutover); the fundamentals feature (waits for the owner's go); the phones.

## The old app here

Surveyed 2026-09-26 on `a9fd11ad`. Each becomes an entry in `docs/old-app-mistakes.md` "Running it (stage 5)" (four are there already) with the test that guards it.

**Data flow.**
- **Every change rebuilds the whole document and diffs it.** Every commit rings the bus (`server/src/events.rs:74`); each open stream rebuilds all of `Figures` (`events.rs:274-287`, `wire/build.rs:358`) and diffs it against what it sent (`events.rs:361`); every watched document is re-read and diffed on every step whether it moved or not (`events.rs:372-388`). The engine already reports what moved per entity and field (`engine/src/engine.rs:45-65, 283`), held equal to a fresh build by a test (`server/src/figures.rs:454`), and the server throws it away (`figures.rs:197-202`; `due.rs:123,156`). **Instead:** the report drives the send (Approach A).
- **Every open loads everything.** The first message is all of `Figures`: every trade, every position, the cashflow, and the markets context with every stored news item uncapped (`wire/figures.rs:514-541`, `model/src/markets.rs:301-304`); about 1 MB on a real book. No list is paged (`web/src/lib/Trades.svelte:70`, `markets/News.svelte:317`). **Instead:** subscriptions per screen, paged lists.
- **Numbers per connection, no resume.** The SSE id restarts at 1 on each connection (`http/stream.rs:80-82`); a gap or a reconnect sends the whole state again (`events.rs:327-332`, `web/src/lib/live.ts:163-172, 292`). **Instead:** one sequence per book; `Last-Event-ID` resumes.
- **Nothing kept between opens** but display preferences in `localStorage`; no read answered "unchanged" (`Cache-Control: no-store` on every answer, `http/mod.rs:233`). **Instead:** the browser's database and conditional reads.
- **Quotes for everything held, twice.** `due::pass` quotes every holding every minute while a page is connected (`due.rs:35,117-124`) and `feeds::quote_loop` quotes the watchlist and tiles every minute (`feeds.rs:2669-2683`). **Instead:** one quote demand, from what the open subscriptions show (the header's totals include every holding, so holdings are always shown while a page is open; the watchlist and tiles only while their card is on screen).
- **The markets context runs on the old model**: `wire/context.rs:29-69` converts the engine's positions to the old `f64` `Position` and calls `bagholder_model::markets::markets_view`; the page formats floats for it (the four allow-list entries). **Instead:** built from the engine's positions in exact decimals, a subscription of its own.
- **Two waits are not in `TIMED_WAITS`**: the ticket quote (`docs.rs:38,48`) and the stream's keep-alive (`stream.rs:83`), because the test's patterns miss them. **Instead:** the test finds every wait by what it calls, fed a violation of each form.

**Failures.** The survey counted, outside tests, 30 `.ok();`, 85 `let _ =` and 133 `unwrap_or_default()` in the server crate alone, with the market crate next. The consequential ones: the feed passes open the store with `.ok()` and a store that will not open turns every pass into nothing (`feeds.rs:86-88`, used 41 times); writes discarded (`feeds.rs:2067, 1513-1516, 1728, 1836-1905`; `market/src/refresh.rs:165-172`; `market/src/exposure.rs:1088`); a notification's "told" mark discarded, so it can be told twice (`feeds.rs:782, 1195`); reads that fail read as empty (`feeds.rs:310, 324, 760-778`; `status.rs:65-136` answering `ok:true`; `session.rs:377` a default session; `broker_reads.rs:182-189` "not signed in"); bar pulls discarded (`market/src/history.rs:553-555, 951-954, 1177, 1247`); the short-interest sources only print (`market/src/shorts.rs`); a watchlist move that can lose a row (`main.rs:201-208`); a rollback's restore discarded (`update.rs:514-516`). The server's `log()` only prints (`app.rs:343-345`). The header's health is one joined string (`status.rs:74-110`, `sources/src/health.rs:124-139`). A book that cannot open exits before the port is bound, so the browser shows its own connection error (`main.rs:108-148`). On the page, a failed watchlist change resyncs silently (`state.svelte.ts:131,146`), and several calls drop their answer (`ui.svelte.ts:193-206`, `notes/channel.svelte.ts:58-111`, `live.ts:236,273`).

**Access.** The peer check applies only when the bind is exactly `127.0.0.1` (`http/mod.rs:276-279`); the container binds `0.0.0.0` and runs as root (`rust/Dockerfile:36-47`), so any peer that reaches the port places orders with `Host: 127.0.0.1:1` and any `X-Bagholder` header (`http/mod.rs:268-269, 291-298`; the page sends the constant `'1'`, `web/src/lib/api.ts:28`). No Origin check. Broker session in plain JSON beside the book (`ws/src/session.rs:176`), mode 0600 with a failed `chmod` ignored. The only MCP server is the filings one: stdio, protocol 2024-11-05, calling SEDAR+ and EDGAR itself, and its `disclosures_document` tool writes to any path the caller names (`market/src/bin/disclosures-mcp.rs:158-166`). Routes are declared once by `api_routes!` (`http/mod.rs:166-193`), but the streams and two routes sit outside the table (`mod.rs:219-225`), and the table carries no descriptions, no JSON Schema and no read/write kind.

**Running.** Health after an update is "still alive after 20 seconds" (`update.rs:20-21, 716-722`); a child that exits 0 inside that window is not rolled back (`update.rs:729`); a crash outside an update ends the supervisor (`update.rs:741`); migrations snapshot the book and market cache before they run (`sqlite/src/migrate.rs:170-232`) but nothing restores a snapshot, so a rollback puts the old binary beside a book it refuses as "written by a newer version" (`migrate.rs:164-166`); nothing waits for an order in flight (`update.rs:635-657`); checksum only, no signature (`update.rs:535-556`; `release.yml`); no service install anywhere.

**Carried over, and why:** the SSE transport (the HTML standard's reconnect with `Last-Event-ID` is exactly the resume §13 asks for); the `set`/`del`/`rows` patch ops and the page's in-place writes with their element tests (`tick.svelte.test.ts`, `changes.svelte.test.ts`: the kept half of §13, "Keep" in the design review); `api_routes!` and the `ts_rs` generation (§12's one declared interface; this plan completes it rather than adding a second); the in-binary supervisor and archive swap (they work; what is wrong is what counts as healthy and what is restored); the migration snapshots (right, and now used).

## How the leading products do it

Trading journals (TradeZella, Tradervue, TraderSync, Edgewonk) are hosted services and document none of this; the references are the standards and the tools that solve the same problem for a program on the person's own machine. All read 2026-09-26.

- **Numbered changes and resume.** The HTML standard's server-sent events: an `id:` sets the last event id, and on reconnect the browser sends it as `Last-Event-ID` (https://html.spec.whatwg.org/multipage/server-sent-events.html). Replicache's pull answers a client's cursor with a patch of `put`/`del`, and with `clear` then `put`s when "the request cookie is invalid or not known to the server" (https://doc.replicache.dev/reference/server-pull). Firestore's listen stream has `RESET` for a target the client must drop and refill (https://docs.cloud.google.com/firestore/docs/reference/rpc/google.firestore.v1). Taken: one sequence per book as the event id; a resume inside the kept window gets the changes since, one outside it gets `clear` and the subscription's state, per subscription.
- **Subscribe to what is shown.** Market-data streams subscribe per symbol and channel and unsubscribe when done (Alpaca, https://docs.alpaca.markets/docs/real-time-stock-pricing-data; Massive, formerly Polygon, https://massive.com/docs/websocket/stocks/quotes). Taken: a subscription per screen, and quotes read for what open subscriptions show.
- **Conditional reads.** RFC 9110: an ETag is an opaque validator; `If-None-Match` that matches gets 304 with no body (§8.8.3, §13.1.2, §15.4.5, https://www.rfc-editor.org/rfc/rfc9110.html). Taken for every on-demand read.
- **Keeping state in the browser.** IndexedDB is per origin, versioned through `onupgradeneeded` (https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB); storage is best-effort and can be evicted whole, and Safari deletes it after seven days without use (https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria). Taken: what is kept is a cache that makes an open instant, never the only copy of anything; an evicted store means a full first load, which is correct, only slower. A normalized store keyed by entity id is what Redux, RTK and Apollo recommend (`briefs/reference.md`, "Normalized stores").
- **A local app and other websites.** OWASP: tokens on every state-changing request, and reject non-safe methods when `Sec-Fetch-Site` is `cross-site` (https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). A custom header does not stop DNS rebinding, which is why Transmission added a Host allow-list (CVE-2018-5702, `briefs/reference.md`); Syncthing checks the browser is talking to localhost against rebinding (https://docs.syncthing.net/users/faq.html); Jupyter rejects non-local Host headers and has a token on by default (https://jupyter-server.readthedocs.io/en/latest/operators/security.html). Chrome's Local Network Access prompt (Chrome 142) does not remove the server's own duty (https://developer.chrome.com/blog/local-network-access). Taken: Host and Origin checks on every request whatever the bind, `Sec-Fetch-Site: cross-site` refused on writes, a real per-install token, and a key when listening beyond loopback (item 2).
- **MCP.** Protocol revision 2026-07-28: tools listed with a JSON Schema `inputSchema` (2020-12), an optional `outputSchema` whose `structuredContent` must conform, errors as `isError` results, "a human in the loop with the ability to deny tool invocations", servers must validate inputs and sanitize outputs (https://modelcontextprotocol.io/specification/2026-07-28/server/tools); a local server should use stdio, or on HTTP validate Origin and bind to localhost (https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http, https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices). Taken: `bagholder mcp`, a stdio server built into the binary, speaking to the running app over loopback with its own token; tools and schemas generated from the route table; outside text wrapped as such.
- **Signed updates, health by answer.** Sparkle signs every update with EdDSA against a public key in the app (https://sparkle-project.org/documentation/publishing/); Tauri's updater "needs a signature … This cannot be disabled" (https://v2.tauri.app/plugin/updater/); TUF lists rollback and freeze attacks a checksum alone does not stop (https://theupdateframework.io/docs/security/). Kubernetes judges a started program by a probe's answer, not by its being alive (https://kubernetes.io/docs/concepts/configuration/liveness-readiness-startup-probes/). Taken: Ed25519 signatures (OpenSSL, already a dependency) checked against a key in the binary; healthy means the health route answered with the book open.
- **Running as a user service.** launchd LaunchAgents in `~/Library/LaunchAgents`, and a job "must not daemonize" (https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html); systemd `Restart=on-failure` "is the recommended choice for long-running services" (https://man7.org/linux/man-pages/man5/systemd.service.5.html); Syncthing installs a LaunchAgent, a `systemctl --user` unit, or a Task Scheduler task at logon (https://docs.syncthing.net/users/autostart.html). Taken the same three.
- **Showing a failure where it applies.** Interactive Brokers states per request which kind of data is delivered (live, frozen, delayed) (https://interactivebrokers.github.io/tws-api/market_data_type.html); TradingView marks a delayed chart on the chart itself (https://www.tradingview.com/support/solutions/43000476233-the-countdown-is-not-displayed-on-the-chart/). Taken: health per source on the wire, shown on the card it feeds and in the header while it persists (§15).

## Open questions

- **How long the server keeps changes for a resume.** Objective: a reconnect after a short gap (a laptop lid, a network change) gets only what changed. Known: an out-of-window resume is still correct (it gets `clear` and state), only larger. Settled by measurement while building: the kept window is sized by count and bytes, not time; the second-open test and the request budget fix the numbers, which are written into the plan's Verification.
- **Whether the keychain is reachable in every place the app runs.** Objective: credentials outside the book. Known: macOS has the login keychain, Windows the Credential Manager, a Linux desktop the Secret Service; a Linux server and the container have none. Settled by the design: the keychain where the platform has one, otherwise a file only the person's account can read (0600, with a failed `chmod` a failure, not ignored), as §12 already says.

## Approach

### A, data flow

- **Book id.** A random id written at the book's creation (book migration 014, schema snapshot `v14.sql`), new after Clear all. The browser's store is keyed by it and `PROTOCOL`.
- **Change log** (`server/src/changes.rs`, new): the engine's `Moved` for each `apply` is turned into wire rows by entity: for each moved entity only its own wire row is built (the builders in `wire/build.rs` split per entity; the header totals rebuilt, which is a sum). Each committed change gets the next number of the book's sequence; the log keeps the recent changes in memory (bounded by count and bytes). `Moved`'s fields are compared by value, not by `Debug` text (`engine.rs:67-74`).
- **Subscriptions** (`server/src/subs.rs`, replacing `Feed`'s whole-document rebuild): one per screen, declared as typed keys (`header`, `positions{filters}`, `trades{filters, sort, window}`, `cashflow{filters}`, `income{…}`, `markets`, `news{window}`, `instrument{id}`, `orders`, and the existing on-demand documents). A subscription knows the entity ids it holds; a change reaches it only if it touches one of them or its filter would now include it. The stream carries `snapshot`, `patch` and `clear` per subscription, each with the book's sequence as its SSE id. A reconnect with `Last-Event-ID` inside the window gets the patches since; outside it, `clear` and state. A filter change opens a new subscription; rows in both are kept by the page.
- **Paged lists.** `trades`, `news`, distribution history and orders send the window in view plus a margin; the page asks for the next window as the person scrolls (IntersectionObserver). A change to a row outside every open window updates the list's count and order keys only.
- **Browser store** (`web/src/lib/store/`, new): IndexedDB, one database per book id and `PROTOCOL`, holding each subscription's last state and sequence and every on-demand read with its ETag. On open the page draws from it at once and subscribes with its sequence; with nothing changed the server sends only an acknowledgement. Cleared when the book id changes or Clear data runs; never holds a credential.
- **Conditional reads.** Every on-demand GET (`history:*`, filings, a document summary, short interest, a universe) answers with an ETag from its version and 304 on `If-None-Match`. A closed session's bars and a filed document carry `immutable`.
- **Quotes on demand.** One demand set, the union of what open subscriptions show; `due::pass` and `feeds::quote_loop` become one quote read over that set. Brackets keep reading Wealthsimple's own quote on their own five-second check (stage 4), whether or not a page is open.
- **Markets context on the new wire.** `wire/context.rs`'s conversion to the old `Position` and `bagholder_model::markets::markets_view` are replaced by a builder over the engine's positions in exact decimal text; its types move from `generated/wire.ts` (the old model) to the server's generated files; the heatmap and the markets cards format decimal text. The four stage-5 entries leave `no_money_arithmetic.test.ts`'s allow-list.
- **Timers.** `TIMED_WAITS` finds waits by what they call (`sleep`, `wait`, `wait_timeout`, `interval`, `park_until*`, `recv_timeout`), fed one violation of each; the ticket quote and the keep-alive are listed with their reasons.
- **`SPEC.md`**: the "refresh cadence" lines that say a screen reloads on a timer are replaced with what triggers the read, per figure (the quote read while shown, each source's own cadence), with the reason "load only what changed" (`docs/decisions.md`, 2026-09-20).

### B, failures shown

- **Health per source** on the wire as a typed list (`Health { source, what_failed, since, words }`) replacing the joined `Status.error`; the header lists what is failing now, each card shows its own source's failure in its place. Structured by the sources that already carry health (`sources/src/health.rs`) and extended to the feeds, the market crate's readers, the store and the updater.
- **The server's `log()`** writes the failure into the health list it belongs to; a line that belongs to no source is a failure of the app, shown in the header.
- **Each discarded error in the survey fixed at its site**: a store that will not open fails the pass and says so; a write that fails fails its operation; a read that fails is the source's failure, never an empty list or a default; the watchlist move is one transaction.
- **A book or migration that fails still binds the port** and serves the page with only the failure (what failed, and the snapshot it was taken before); `/api/status` answers it.
- **The page**: every call's failure is shown by the caller that made it (the watchlist change, sign-in cancel, disconnect, the notes channel, events watch and resync); `api.ts`'s `{ok:false}` becomes a typed failure the caller must handle (the type checker enforces it).
- **Scan test** (`server/src/tests_boundary.rs`, extended to every crate): `.ok();`, `let _ =` on a `Result`, `unwrap_or_default()` on a `Result`, and `if let Ok` without `else` on I/O are refused outside tests unless listed with a reason (as `TIMED_WAITS`), fed a violation of each form. The page's scan refuses an empty `catch` and a dropped `call(...)`.

### C, access and agents

- **Every request, whatever the bind:** Host must be one of the addresses the app is served on (its bind address and port, plus `BAGHOLDER_HOSTS` for a reverse proxy); a request with an `Origin` must carry the app's own; a write with `Sec-Fetch-Site: cross-site` is refused. The peer check stays for loopback binds.
- **Write token:** a random token per install (`home/page-token`, 0600), put into the served `index.html` as a meta tag and sent by `api.ts` on every write; the constant header goes.
- **Beyond loopback (item 2):** the key, entered once per browser, kept in an `HttpOnly; SameSite=Strict` cookie; without it, every route but the key page answers 401. The container runs as a non-root user.
- **Credentials:** the Wealthsimple session moves from `session.json` to the keychain (the `keyring` crate: one crate for the three platforms' stores, weighed against three hand-written bindings; listed in `ws/Cargo.toml` with why), else the 0600 file; a copied book never carries it.
- **One interface:** `api_routes!` gains a one-line description and a kind (`read` or `change`) per route, and the streams and the two routes outside the table join it. JSON Schema for each request and answer is generated from the same types (`schemars`, beside `ts_rs`, listed with why; the generated schema is a blessed file like the TypeScript).
- **`bagholder mcp`** (a subcommand of the one binary, stdio, protocol 2026-07-28): its tools are generated from the table (name, description, `inputSchema`, `outputSchema`, `readOnlyHint`/`destructiveHint` from the kind); it calls the running app over loopback with its own token (`home/agent-token`), so every request is recorded as `agent`. Order tools per item 3. Text a source wrote (headlines, filing text, document summaries) reaches the agent inside a typed `outside` wrapper that says so. The filings tools become routes of the app like any other; `disclosures-mcp` and its path-writing tool are removed, and `rust/mcp/manifest.json` points at `bagholder mcp`.

### D, running

- **Supervisor:** respawns the server after a crash (backoff 1, 5, 30 s; a crash loop of five in ten minutes stops and leaves the failure page's record), not only after an update.
- **Update:** refuses while any order request is in flight at the gate (`sending`, `sent, not confirmed`, `cancelling`) and waits for it to settle; takes a snapshot of the book and the market cache (`VACUUM INTO`, the migration snapshot's code) and records it in the `update-pending` marker; swaps; the new child is healthy only when `GET /api/health` answers with the book and market cache open and migrated, within 60 s. Otherwise, whatever its exit code: the previous files and both snapshots are restored, the marker becomes `update-failed`, and the previous copy starts and says so in the header. A restore that fails is itself shown, never discarded.
- **Signed releases (item 4):** `release.yml` signs each archive with Ed25519 (`openssl pkeyutl -sign`, the key from a repository secret) into `.sig` beside the `.sha256`; `update.rs` verifies with the public key compiled in (OpenSSL, already a dependency) before extracting. A release without a valid signature is not installed, and the header says why.
- **Service (item 1):** `bagholder service install | uninstall | status`: a LaunchAgent with `RunAtLoad` and `KeepAlive` on the Mac, a `systemctl --user` unit with `Restart=on-failure` on Linux, a Task Scheduler task at logon on Windows; the service runs the supervisor. A release install runs `install` on first start if item 1 is taken. The container keeps no updater (compose restarts it) and says when a new image exists, as now.
- **`README.md`**: the update section's wrong path for the Rust build (`README.md:132`) and the new service lines.

**`SPEC.md` changes**, in the part that makes them: refresh cadence per figure (A); source failures on their cards and in the header (B, already `docs/architecture.md` §18); the key page (C, if item 2 is taken); the update's states "waiting for an order to settle" and "returned to vX.Y.Z" in §2 Versions (D).

**Stays the same:** every screen, card, figure and word `SPEC.md` gives; the SSE transport and patch ops; the stage 4 gate and bracket cadence; the old `bagholder.db` for settings, feeds and notifications (stage 6).

- [ ] `npm run check`, `npm test` and `npm run e2e` green in `web/` (e2e in CI's browser job); screenshot baselines unchanged except where `SPEC.md` changed.

**A1, data flow**

## Verification

### A1, data flow (branch `stage-5-interface-and-running`, 2026-09-26)

Departures from the approach above, each for a reason found while building:

- **Resume is per subscription, by version, not by replaying numbered changes.** Each state sent carries its version (a hash of what it says, `views::version_of`); a page opening or reconnecting says the version it holds of each subscription, and is answered `same` or sent the state, which it reconciles into what is shown, so no element that did not change is touched. A replay from `Last-Event-ID` would need the server to keep, per page, what each subscription looked like at every number; the version answers the same question with nothing kept. The engine's changes are logged by version (`Figures::moved_since`, 256 kept) only to bring an open subscription forward.
- **The book's id lives in its settings, not in a migration**: made the first time it is asked for, made again by Clear data (`Book::id`, `Book::renew_id`).
- **A tab's screen is subscribed while it is open, and kept on the page after**: going back draws what is held at once and asks with its version, rather than keeping every visited tab's subscription open.
- **The browser keeps what it read on demand in its own HTTP cache**, revalidated by entity tag (`private, no-cache`), rather than in the page's database: the same keeping and "unchanged" answer, with nothing written for it.
- **Quotes are read for what a screen shows by kind of screen** (`due::PRICED`): the holdings are all on any screen that shows a price (their total is on it), so the demand is the holdings' while one is shown, the watchlist's and tiles' while the Markets tab is.
- **The engine reports the broker's statement of an account** (`Entity::Broker`): the test holding every screen to a fresh build found a change to an account's cash moved nothing the report named.
- **Paging at scale**: the windowing is by count, tested on the recorded month (`a_long_list_is_sent_as_far_as_the_page_has_scrolled`), not on a synthetic 20,000-trade book.
