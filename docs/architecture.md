# Bagholder architecture: the Rust + Svelte build

This is the design of the application going forward, and the order of work that gets it there. The Rust server with the Svelte page is the only build being developed; the Python and Go servers and `ledger.html` are frozen and are deleted at cutover (stage 9). `docs/frontend-backend-migration.md` records why this stack was chosen (axum on tokio, a Svelte SPA built by Vite, TypeScript types generated from the Rust structs); this document supersedes its phases, which described a port of the page and left the server as it was.

`SPEC.md` remains the authority for every figure, screen and interaction. Where this document and the code disagree, the code is wrong.

## Where the code stands (audit of 2026-09-20)

Six reviews of the branch, each claim carrying a file and line, the consequential ones re-checked by hand. The short of it: the server is a line-by-line translation of a Python standard-library program, and the page is a transliteration of `ledger.html`'s render functions. Both work; neither is designed.

**Server (`rust/`, ~39,000 lines).**
- HTTP is `tiny_http` with an unbounded OS thread per request, two `match path` string routers, hand-written query and body parsing (a malformed or oversized body silently becomes `{}`), hand-written chunked framing for the two streams, panics used as exceptions under `catch_unwind`, `Cache-Control: no-store` on content-hashed assets, no graceful shutdown, no signal handling.
- State is one global `APP` of mutexes, every lock taken with `.lock().unwrap()`; a `syncing` flag that a panic leaves set forever; a `jobs` map that only grows.
- SQLite: a new connection per call (34 sites), **no WAL and no transactions anywhere** (the Python build sets WAL; a database created by the Rust build never is), replace-by-delete-then-insert row by row in autocommit, so a reader can see an empty table and a crash leaves a half-merged book.
- The data model is `serde_json::Value` (~1,800 mentions against ~60 structs): enums compared as strings in hot loops, a missing number read as `0.0`, a missing FX rate read as `1.35`, any non-USD currency treated as CAD, quotes keyed by symbol alone (the coin/share collision is patched by hand), about four deep copies of the trade list per request.
- The model cache keys on one fingerprint that includes quotes, so **every quote tick re-reads every activity and re-runs the FIFO match** (up to twice), which `SPEC.md` §Freshness forbids and the Python and Go builds do not do. The cache has no single flight, so concurrent requests each rebuild. The fingerprint itself is ~36 SQL statements, computed about four times per `/api/model`.
- Seventeen background loops run on fixed periods whether or not a page is open or a market is trading; each sleeps in 250 ms slices (about 70 wake-ups a second, idle). Margin, news and universes are rewritten with `fetched_at = now` when nothing changed, which moves the fingerprint and makes every open page refetch the whole book. No conditional requests anywhere. EDGAR and SEDAR+ pacing sleeps while holding a lock, so a click queues behind a sweep.

**Page (`web/`, ~8,300 lines).**
- One `store.model` replaced wholesale on every load: every derived value re-runs, every row re-renders, and the open trade's chart is destroyed and rebuilt. `only=live` and `/api/trade` are never called, so a quote tick downloads the whole book; the reload lands under a user who is typing or has a trade open.
- Nine polling loops (status at 2.5 s/30 s, sync 1.5 s, connect 0.5 s, orders 10 s, ticket quote 5 s, tiles 3 s and 9 s blind full reloads, shorts 4 s, history 3 s, filings 1.5–15 s), though an SSE channel already exists. About forty `loadModel()` call sites, most of which need one row or one section.
- Five copies of an `api()` helper, four implementations of symbol search, two implementations of the filings store; hand-written types with index signatures and `as unknown as` casts (`Status` lacks the very `coreVersion` field the contract turns on).
- 646 inline `style=` attributes; the sortable header written six times, the modal shell three times, the panel shell three times; no focus management in any dialog, rows that cannot be reached by keyboard, no `aria-sort`; eight dead files; no ESLint, no component tests, no browser tests; **`web/dist` committed to git** while gitignored, and nothing in CI builds or checks `web/`.
- **About 45 features of `SPEC.md` are missing or partial**, among them: the listing page for a ticker the book does not hold (every such click goes nowhere), the update button with its progress and the "Restart Bagholder to finish the update" line, the first-run page, Shift+Enter / Backspace / the Tab ring in the filter popover, ⌘K over the Orders panel, scroll restoration on Back, loading skeletons, the digit roll, the cut-text hover, scrollbars (never shown), browser-channel notifications and the test notification, the heatmap's own address and slideshow. The full checklist is kept in `docs/parity.md` and is closed item by item in stage 7.

## Rules the design holds to

Each of these is enforced by a test that fails when it is broken (stage numbers say where the test arrives). A rule without a test is a wish.

0. **The unit of update is the element, never the screen.** This is the reason the page was rebuilt on this framework, and every other rule serves it. When one value changes, the one element showing it changes, and nothing else on the page is re-rendered, re-evaluated or re-fetched: not the screen, not the card, not the table, not the row beside it. A price moving on one holding writes that holding's last, market value, unrealized and day change, and the few totals that include it, into the objects already on screen; the other holdings, the trades, the charts and every other tile are untouched. A grade set is one cell. A listing watched is one row inserted. A headline arriving is one row inserted. So, end to end: the server works out *which entities and which fields* a change moved and sends those and only those, keyed by id; the page holds each entity as one stable object and writes the changed fields into it; the framework's fine-grained reactivity touches the text nodes bound to them. Nothing in that path is a "view", a "section" or a "half" being replaced. The test watches the live DOM across a change and fails if any node outside the changed elements is mutated. (The slice after stage 2, then every kind of change.)

1. **Work happens because something changed, and only the work that change requires.** No loop runs on a fixed period when an event, a deadline or a request can drive it. A periodic read survives only where the upstream offers no push; it then runs only while someone is looking at what it feeds, only while that market is open, with backoff, jitter and conditional requests, and it is listed in "Timers that remain" below with its reason. (Stages 2–3, 6.)
2. **The server tells the page; the page never asks "anything new?".** One SSE connection carries typed events. (Stages 3, 6.)
3. **A derived value is recomputed only when one of its own inputs moved.** A quote tick re-marks open positions and nothing else; a journal edit recomputes nothing. (Stage 2.)
4. **A write that changes nothing is not a change.** Writers compare before they replace; versions move only on a real difference. (Stage 1.)
5. **Types, not blobs.** Domain data is structs and enums from the SQLite row to the HTTP response; the page's types are generated from them. A missing value is an `Option`, never a default that looks like data. (Stages 4–5.)
6. **The database is never observed half-written.** WAL, one writer, every multi-row change in a transaction. (Stage 1.)
7. **Nothing on screen is rebuilt that did not change**, and nothing changes under a user who is typing. (Stage 6.)
8. **Every feature in `SPEC.md` exists and is driven by a browser test**, not only rendered. (Stages 7–8.)
9. **Money is never silently wrong**: an unknown currency or a missing rate is reported, not converted at a constant. (Stage 5.)

## Target design

### Process and HTTP
One tokio runtime. An axum `Router` under a tower stack: the loopback/Host/same-origin gate as middleware, request timeout, body limit, panic catcher, compression, tracing. Every route has a typed request (`Query<T>` / `Json<T>`) and a typed response; one `ApiError` enum maps to real status codes. State is an `AppState` passed by `State<…>` — no global. Static assets are embedded in the release binary and served `immutable` when hashed, `no-cache` for `index.html`; a debug build reads `web/dist` from disk and development uses the Vite proxy. Graceful shutdown on SIGINT/SIGTERM and on the updater's restart, inside the supervisor's existing contract (exit code 3, `BAGHOLDER_CHILD`, the pending-update marker, the 20-second health window), which does not change. The MJPEG sign-in stream becomes a body stream over a `watch` channel fed by the blocking CDP thread, its part-boundary framing and newest-reader eviction preserved. `bagholder-browser` stays a separate process, called with a timeout. Logging through `tracing`.

### Storage
`rusqlite` stays (the store crate is synchronous and tested). A pool of connections lent through `spawn_blocking`; a writer takes its turn inside SQLite (IMMEDIATE transactions under the busy timeout), so there is no writer thread in front of it. Pragmas once: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`. Sync, import, clear and every replace run in a transaction. Schema migrations are versioned and the stored version is consulted. **Each thing the model reads has a generation counter, kept by triggers the store generates from each table's columns**: an insert or delete moves it, an update moves it only when a data column differs (never for a `fetched_at` alone), and a replace-style writer keeps its writes only if the rows differ afterwards. No writer can forget a counter or move one for nothing. They replace the COUNT/MAX fingerprint (~36 statements a look, blind to edits in place) with one statement. Anything that copies the database checkpoints first.

### The model: layers, each keyed by what it reads

| Layer | Reads | Rebuilt when |
|---|---|---|
| Book (normalize, FIFO match) | activities, securities, the day | an activity or a security changes, or the day turns |
| Closed trades | Book, FX, saved groups | those move |
| Journal overlay (joined at serialization) | journal | never recomputes anything |
| Cashflow rows | Book, FX, distributions | those move |
| Equity curve and years | NAV history, benchmarks, the day | those move |
| Accounts | accounts, balances, margin | those move |
| Marked positions | Book's open lots, quotes, Accounts | **a quote tick rebuilds this and nothing above it** |
| Markets | marked positions, exposures, news, universes, tiles, watchlist | those move |

Each layer is an `Arc` behind its key with a single-flight build. The page is sent a whole view only when it opens, changes its filters, or reconnects after a gap. From then on it is sent **changes**: for each change to the model, the entities whose fields moved, each as its id and those fields, and the aggregates that moved with them (rule 0). The server finds them by comparing the rows of the layer it rebuilt with the rows it held before -- by id, field by field -- so a tick that moves one price yields one position's four figures and three totals, not a list of positions. Filters stay server-side: the aggregates are model outputs and the page must never re-derive money math; a change is computed per filter set in use.

### Domain types
`Activity`, `Fill`, `Lot`, `Leg`, `Trade`, `Position`, `CashflowRow`, `Account`, `Balance`, `MarginRow`, `Security`, `Quote`, `Distribution`, `FxTable`, `EquityPoint`, `Filters`, and the payload structs, with enums for currency, kind, side, direction, category, flag, raw event, grade, price source. Identity is an `InstrumentKey` (security id, or symbol + kind + currency), never a bare symbol. Quantities are exact (`Qty`, 1e-8 units) because trade ids are derived from them; money is a `Native`/`Cad` newtype over `f64` so units cannot be mixed; conversion returns a `Result`. TypeScript types are generated with `ts-rs`, including the event union, and the page has no hand-written API type.

### Events
An in-process bus with a sequence number and a short ring buffer. Writers publish where they commit: `QuotesChanged{keys}`, `BookChanged`, `AccountsChanged`, `NewsChanged{key}`, `FilingsChanged{symbol}`, `FilingEnriched{symbol,id}`, `ShortsChanged{key}`, `UniverseChanged{key}`, `TilesChanged`, `OrderChanged{id}`, `BracketChanged{id}`, `HistoryReady{key,tf}`, `SyncProgress{step}`, `SessionChanged`, `UpdateState`, `NotificationCreated{id}`. `GET /api/events` is the one SSE stream; `Last-Event-ID` replays from the ring and a gap makes the page reconcile once. A live event carries its payload, so a tick needs no fetch. The page tells the server what it is showing (`POST /api/view`: route and instrument keys); subscriber and view state is what lets the periodic reads below run only when watched.

### Background work
Tasks on the runtime with cancellation, no sleep-polling of a stop flag. Deadlines instead of periods where the next moment is known (token expiry, next pull due). On demand where a page asks (universes, fear and greed, shorts, exposure on a security change). Interactive requests get priority over sweeps at every paced upstream, and no pacing sleep holds a lock.

**Timers that remain, and why** — each upstream below has no push interface. The list is enforced: a test (`test_no_wait_on_a_clock_that_is_not_accounted_for`) counts every wait on a clock in the source by file, and a new one fails it until it is either replaced by waiting for the thing itself or argued for here.
- Quotes (TMX, Yahoo, Coinbase, Cboe): each minute, only while a page is open, and only for listings whose market can have moved since they were last read (`quotes::can_have_moved`; Coinbase always). The ticket's live quote: every 5 s, only while that ticket is open.
- Wealthsimple order status: closely only while an order is live or the Orders panel is shown, otherwise every five minutes (an order placed in Wealthsimple's own app has no other way in). The bracket engine: parked until a bracket is armed; its cadence is what a stop needs and is not relaxed.
- Wealthsimple portfolio: only while a page is open. The activity pull and the token: slept until their computed moment (the next weekday pull time, the token's expiry less its margin), woken early by a sign-in or a disconnect; only a failure is retried on a period, doubling from 30 s to 30 min.
- News: only while a page is open or a news notification is on. The filings sweep: only while a Disclosures or Releases notification is on, every five minutes. Short interest, the heatmap universes, fear and greed: only while shown.
- The intraday archive: works while something is due, then sleeps until the oldest stored read passes its top-up age or the book gains a listing. The document reader: waits for a filing to be stored or the local model to come up.
- FX, benchmarks, distributions, the release check: an hourly look at what is due -- the Bank of Canada's 16:30 rate, a benchmark a day behind, a payer's record past its age, six hours since the last attempt -- which reads the store and asks nothing unless something is. Several moments decide it and none is more than hours away, so the look stays hourly rather than being one computed deadline per condition.
- CSV folder watch: every ten minutes, only while a folder is set. The standard library has no file-system notification; the `notify` crate would bring a back end per operating system for a folder that changes a few times a year, and does not earn its place.
- Request pacing: one limiter per host (`market::pace`): a caller takes the host's next free moment and waits for it with no lock held. The SEC, fund-company sites, news feeds, and the archive's backfill at TMX (250 ms apart on one connection; a chart someone is waiting for is not paced). Yahoo keeps its own gate because it also backs off after a 429; SEDAR+ is paced inside its one browser-like session, which is used by one caller at a time by nature.
- Child processes (the supervisor in the twenty seconds after an update, `pdftotext`, the local model coming up, the sign-in browser): the standard library has no wait with a deadline; tokio's does, in stage 4.
- The stream's 15 s keepalive and 40 ms gather window: transport, not polling.

### The page
One typed API client (generated types, one `request<T>`, abortable, always carrying the header). One `EventSource`. State is separate `$state.raw` slices — core (per filter set), live, markets sections, accounts/options, status, orders, notifications — each replaced only by the event or response that owns it, rows held by id so an edit patches one entry. A full core apply waits while an input has focus or a trade is open; live applies at once. Per-instrument data (history, filings, shorts, listing, search) comes through one resource cache: keyed, in-flight de-duplicated, aborted when nothing is subscribed, errors expiring. Mutations are optimistic: patch, send, reconcile from the response, roll back on failure; a full reload is never the success path. Charts update their series in place.

Structure: shared components for the sortable header, grid header, dialog and side-panel shells, clickable row, pills, donut, hover crosshair; one overlay manager owning stacking, Escape order, outside click, focus trap and focus return; one shortcut table. Styles move from inline strings to tokens and component-scoped CSS, declaration for declaration, each screen gated by a computed-style and screenshot comparison at 1200, 1340, 1440 and 1680 px — nothing about the look changes. ESLint, Prettier, strict TypeScript, Vitest for logic and components, Playwright driving every interaction in `SPEC.md`.

## Order of work

The app stays runnable after every stage; each stage lands with the tests that hold its rule.

0. **Guardrails.** CI builds, checks and tests `web/` on every PR; `web/dist` leaves git and is built by CI, release and Docker, embedded for release; dead files deleted. Freeze the wire contract: ordered, unrounded JSON snapshots of every endpoint for the shared cases, plus new cases for quotes, a split, a stock distribution and saved groups — the net under stages 2, 4 and 5. `docs/parity.md` written from the checklist.
1. **Storage.** WAL, transactions (begun IMMEDIATE), generation counters kept by triggers, replace-only-if-different. *Done.* The writer thread and reader pool arrive with `AppState` in stage 4: built now they would hang off the global that stage removes. Versioned migrations arrive with the typed store in stage 5.
2. **Layered model cache**, single flight. *Done*: each input is read again only when its counter moved and each layer rebuilt only when an input it reads did, so a quote tick reads the quotes and re-marks the positions and the match is not run again (tests hold the layers pointer-equal, and the layered base equal to one built from scratch). A built view is shared per base, filter set and open trade, so the same data asked for again costs nothing. On a real book: a tick 368 ms → 40 ms, the same model asked again 111 ms → 7 ms. What stage 2 did *not* do is change anything on screen: the server still answers a change with a whole view and the page still replaces its whole model with it. That is put right next, by rule 0, not by cutting the view into halves -- a half is still a swathe.
2b. **Element-level updates, end to end (rule 0)** -- brought forward, because it is the point of the whole effort and the first thing a person at the screen can see. The change feed (`/api/events`, SSE) carrying per-entity field changes for a price tick; the page's store holding each entity as one stable object, patched in place; the whole-model replacement and the status poll removed for that path; a browser test that watches the DOM across a tick and fails if anything but the changed elements is touched. Then the same for every other kind of change (journal, watchlist, news, orders, sync progress, tiles, filings), one at a time, each with its test.
3. **Demand-driven background work.** *Done.* Every loop either waits for the thing it serves (`events::park_until`: a page connecting, a document being shown, a bracket armed, a notification switched on, a filing stored, the model coming up) or sleeps until a moment that is known (token expiry, the next pull window, the archive's next top-up, midnight); `App::wait` sleeps in the kernel instead of in quarter-second slices. Measured on a copy of a real book (`BAGHOLDER_LOG_REQUESTS=1` names every request as it leaves): with no page open, **0 outbound requests** over two minutes once start-up had settled, and 0 again after the page closed; it had been about 13 a second, without end -- found by this measurement: the archive asked again on every pass for any listing its source has no intraday bars for, because only a read that found bars was stamped (fixed: a miss is a read; test `test_a_listing_with_no_bars_is_not_asked_again_until_the_next_top_up`). Tests: the timer budget above; parked work starts when a page connects and not before; the pull window and the archive's next-due moment. The typed event bus named under "Events" arrives with the typed model (stage 5): until then the stream compares views, which already sends only what changed.
4. **axum server.** *Done.*
   - *Done (4a):* the HTTP layer is `crates/server/src/http/` -- an axum `Router` on tokio, one module per group of routes (`model`, `markets`, `orders`, `session`, `notifications`, `stream`, `assets`), each route a function with a typed request (`Params<T>` for a query, `Body<T>` for a JSON body) answering `Result<_, ApiError>`; tower layers for the panic catcher, the default headers, the gate, the body limit and a 120 s timeout on routes that answer once. `/api/events` is a task, not a thread: it sleeps on the bell (`events::changed`) and only the comparison (`Feed::step`) runs on the blocking pool; the notification and sign-in streams are bodies fed by their blocking producers. The built page is embedded in the binary (`build.rs`), hashed files served `immutable`, `index.html` `no-cache`. Ctrl-C, TERM and the updater's restart stop it the same way: requests in hand finish (70 ms with a page connected; five seconds at most), inside the supervisor's unchanged contract. `tiny_http`, the two `match path` routers, the hand-written query, body and chunk code are gone. Tests drive the router itself (`http/tests.rs`): the gate, one error shape, the headers, typed bodies, and the stream sending the view once and then only `["set", ["status","syncStep"], …]` for a change to that field. Compression is left out on purpose: the server answers the loopback interface, where it costs processor time and saves nothing.
   - *Done (4b):* the store is pooled (`store::pool`): a connection is lent and given back with its prepared statements, not opened per use; one left inside a transaction is closed, not kept. The header's status went from 2.5 ms to 0.45 ms, the orders list to 0.7 ms. Connections are not split into readers and a writer: under WAL any may read while one writes, and a writer takes its turn inside SQLite (`atomically` begins IMMEDIATE), which a writer thread in front of it would only repeat.
   - *Done (4c):* one per-host limiter (`market::pace`) in place of a pacing function per module; the archive's backfill is paced. The hourly market look and the folder scan stay, for the reasons under "Timers that remain".
   - *Moved to stage 5:* `AppState` replacing the `app()` global -- the typed domain changes every signature in those modules once already, and the two are one pass over them, not two. Routes that hand a JSON object straight to the module that owns it (the order ticket, the sign-in input, the watchlist and tile writes, notification settings) become typed requests with those modules' types in stage 5, and `ts-rs` generates the page's types from them then.
5. **Typed domain model.** *In progress.*
   - *Done (5a):* the model crate is typed from the stored row to the view. `activity.rs` (`RawActivity` read leniently once by `lenient.rs`, then `Activity`; `Kind`, `Side`, `Direction`, `Category`, `Flag` are enums), `input.rs` (accounts, balances, margin, quotes, journal, saved groups, watchlist, news, universes, tiles, distributions, and `Listing`, what the market readers are asked for), `securities.rs`, `exposure.rs`, and `wire.rs` -- every row and block the page is sent (`View`, `Trade`, `Leg`, `Fill`, `Position`, `Portfolio`, `Cashflow` with its three kinds of tile as an enum, `Markets`, …), where a struct's field order is the wire's key order. `normalize`, `synth`, `fifo`, `fold`, `book`, `trades`, `positions`, `cashflow`, `stats`, `filters`, `nav`, `markets`, `view`, `symbols_of` were rewritten on them; a book is keyed by a `BookKey`, not a string split apart again; "has a `flags` key" no longer means "already normalized". The legs and fills of a trade are shared (`Arc`), and a view is built without them except for the open row (`view::Detail`) instead of being built whole and copied without. JSON remains only at the two edges: reading what the store and the shared cases give (`Inputs::set_*`), and `View::to_value` for the stream's comparison. Held by: all 34 shared cases (regenerated: the only change is `0` spelled `0.0`, since a sum is now always a float; Python's and Go's suites still pass on them), 41 wire snapshots byte-for-byte (two new ones cover what none did: watchlist, news merging, universes, the rate tiles, margin and cash, `wsQty`, an unmatched sale), and the payload of a real book (229 trades, 12 holdings, 1,009 news items) identical between the build before and the build after.
   - *Done (5b):* the page's types are generated from the model's (`ts-rs`; `web/src/lib/generated/wire.ts`, held current by `cargo test -p bagholder-model --test types`), and `model.ts` only names them and keeps by hand what has no Rust type yet (the status, the on-demand documents). The first type check against them found three real faults in the page: a watchlist row added without its `kind`, a drawdown amount read as never null, and the cashflow tiles told apart by their label rather than by what they carry.
   - *Left:* the store handing the model typed rows directly (it builds JSON rows that are read straight back into structs); the market, Wealthsimple and order modules' own rows; typed request bodies for the routes that still pass a JSON object through; a typed differ in place of comparing `Value`s; `AppState` for the `app()` global; and rule 9 -- `fx::FX_FALLBACK` still converts at a constant when the book has no rate.
6. **Page data layer.** *In progress.*
   - *Done:* the event stream and in-place writes (2b); every panel's poll replaced by a document on the stream; one client (`web/src/lib/api.ts`: `get`, `post`, `query`, `searchSymbols`) in place of four copies of `api()`, a dozen bare `fetch` calls and three symbol searches -- a test reads the page's own source and fails if anything but `api.ts` calls `fetch` or anything but `live.ts` opens an `EventSource`; the bell is a document on the one stream (a new notification is one row inserted: measured, the badge going from 1 to 2 was a single DOM mutation and no request), so the page holds one connection, not two; the trade chart is made once and an update redoes only what changed -- other bars are new data on the same series, other fills new markers, another theme new options, and a price moving in the card around it touches nothing (it was thrown away and rebuilt on every update; in a browser, switching timeframe now leaves the chart's element in place).
   - *Left:* slices of `$state.raw` where a list is only ever replaced whole; a resource cache for what is looked up on demand (history, shorts, listing); optimistic writes reconciled from the answer everywhere a write exists (journal, watchlist, tiles and notifications do; orders, groups, notes and settings to check); a walk through every kind of change (watchlist, news insert, sync progress, tiles, filings, order fills), each with a DOM and re-run-code test.
7. **Feature completeness**: every open item in `docs/parity.md`, each closed with a Playwright test.
8. **Page structure**: shared components, overlay manager and accessibility, style migration under pixel comparison.
9. **Cutover**: the Svelte page at `/`; `ledger.html`, `python/` and `go/` removed; release, Docker and the updater ship the one build; `SPEC.md`, `CLAUDE.md` and `README.md` rewritten for it.

Stages 0–3 remove the waste a user can feel; 4–5 make the server what it should have been; 6–8 do the same for the page; 9 retires everything else.
